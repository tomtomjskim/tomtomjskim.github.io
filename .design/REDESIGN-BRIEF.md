# 포트폴리오 리디자인 기준

## 문제

기존 화면은 다음 요소 때문에 채용용 기술 포트폴리오보다 생성형 랜딩페이지처럼 보였다.

- 큰 문장과 링크를 묶은 Hero
- 모든 사례를 같은 무게의 ‘대표 사례’로 배치
- 문제·판단·근거를 홈에서 과도하게 반복
- 실무 사례와 공개 연구·개발 자료를 같은 목록에 배치
- 일반적인 작업 방식을 독립 섹션으로 노출
- 면접 준비 자료가 공개 사례에 섞임
- 카드·번호·장식이 내용보다 먼저 보임

  - https://rauno.me/

  - https://pofol.works/

위 사이트의 외형을 복제하지 않는다. 아래 공통 원칙만 사용한다.

1. 첫 화면은 자기소개 광고가 아니라 정보 인덱스여야 한다.
2. 중요 정보는 왼쪽부터 빠르게 훑을 수 있어야 한다.
3. 사례 제목과 한 문장 설명만 홈에 두고 상세 내용은 문서에서 읽게 한다.
4. 실무 경험과 공개 개발 자료를 구분한다.
5. 색·그림자·둥근 카드 대신 글자 위계·간격·구분선을 사용한다.
6. 작업 방식은 독립 홍보 문구가 아니라 각 사례의 확인 과정·판단·구현에서 드러나야 한다.

## 공개 콘텐츠 분류

| 공개 화면에 포함 | 내부 자료로 유지 |
|---|---|
| 이름·역할·짧은 경력 요약 | 면접 예상 질문과 답변 스크립트 |
| 비식별화한 업무 사례 | 공격 질문·방어 답변·리허설 기록 |
| 공개 코드·문서·검증 기록 | 회사별 지원 문안과 Role Adapter |
| 근거 저장소 링크 | Claim 보류·제외 상태표 |
| 사례별 문제·판단·구현·검증·한계 | 범용 작업 절차 체크리스트와 내부 검수 메모 |

웹사이트는 내부 자료를 요약하거나 재서술하지 않는다.

## 홈 정보 구조

```text
이름 / 역할
→ 짧은 경력 요약과 링크
→ 업무 사례
→ 공개 개발 자료
```

### 금지

- Hero
- CTA 버튼 묶음
- ‘대표 사례’라는 승인되지 않은 우선순위
- 2열 프로젝트 카드
- 모든 사례의 문제·판단·근거를 홈에서 반복
- 독립적인 작업 방식 섹션
- 면접 예상 질문·리허설·지원 전략 노출
- 공개 연구·개발 자료를 회사 실무와 동급으로 배치

## 사례 상세

```text
목록으로 돌아가기
→ 사례 구분
→ 제목
→ 핵심 질문
→ 목차와 본문
→ 같은 범주의 다른 사례
```

제목은 문서 제목 수준으로 유지하고 랜딩페이지용 대형 타이포그래피를 사용하지 않는다.

사례 본문은 다음 공개 섹션까지만 사용한다.

```text
문제
→ 업무 환경과 제약
→ 확인 과정
→ 판단
→ 선택 기준과 대안
→ 구현
→ 검증과 실제 사용
→ 한계
→ 근거
```

## 시각 규칙

- 배경: 흰색
- 본문: 검정에 가까운 회색
- 보조 문구: 중간 회색
- 구분: 1px 회색 선
- 색상 강조: 사용하지 않음
- 그림자: 사용하지 않음
- 둥근 카드: 사용하지 않음
- 애니메이션: 사용하지 않음
- 링크: 밑줄 중심

## 승인 경계

- 이번 구조는 ‘대표 사례’를 확정하지 않는다.
- 업무 사례는 현재 공개 가능한 실무 문서 목록일 뿐이다.
- `public-rnd` 분류는 공개 개발 자료로 별도 노출한다.
- 사례 선택과 우선순위는 별도 승인 없이 확정하지 않는다.
- 면접 준비 자료는 `personal-wiki`에만 유지한다.
